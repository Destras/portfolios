# i18n routing (ES/EN) — Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The site serves every page under `/es/…` and `/en/…` through Astro's built-in i18n routing. The two pages that exist today (home and styleguide) are fully translated, and `/` redirects to `/es/`.

**Architecture:** Astro i18n config with `prefixDefaultLocale: true`. Each page is written once, as a dynamic route under `src/pages/[locale]/`, whose `getStaticPaths()` returns `es` and `en`. All prose lives in typed per-locale dictionaries (`src/i18n/es.ts`, `src/i18n/en.ts`) that satisfy one `Dictionary` type, so `astro check` fails when a key is missing. Facts (token names, values, font names, class names) stay out of the dictionaries. `Layout.astro` derives `<html lang>` from `Astro.currentLocale` and emits `hreflang` alternates.

**Tech Stack:** Astro 7.4 (`i18n` config, `astro:i18n`, `getStaticPaths`), TypeScript (strict), `@astrojs/check`.

**Spec:** `design/diseno-juaniw.md` §2 (routes table, `/` redirect) and Annex A.1, A.3 and A.4. They were written for Next.js; the translation to Astro and the overrides below come from the grilling session on 2026-11-24. Copy source: `design/copy-mvp.md` §4.2, §4.3, §4.8 and §4.9. Repo rules: `.claude/rules/design-tokens.md` and `CLAUDE.md` (docs and comments in English).

**Astro docs consulted (astro-docs MCP):**
- `i18n.routing`, `prefixDefaultLocale`, `redirectToDefaultLocale`: https://docs.astro.build/en/reference/configuration-reference/#i18nrouting
- v6 change (`redirectToDefaultLocale` defaults to `false` and requires `prefixDefaultLocale: true`): https://docs.astro.build/en/guides/upgrade-to/v6/#changed-defaults
- `Astro.currentLocale`: https://docs.astro.build/en/reference/api-reference/#currentlocale
- `Accept-Language` detection works only on demand, so it is deferred: https://docs.astro.build/en/guides/internationalization/#browser-language-detection and https://docs.astro.build/en/reference/api-reference/#preferredlocale
- `getAbsoluteLocaleUrl()` / `getRelativeLocaleUrl()`: https://docs.astro.build/en/reference/modules/astro-i18n/#imports-from-astroi18n
- `getStaticPaths()` with `params` and `props`, and its isolated scope (imports only): https://docs.astro.build/en/reference/routing-reference/#getstaticpaths
- Static builds turn redirects into meta-refresh pages: https://docs.astro.build/en/reference/experimental-flags/redirect-page/

**Verified by experiment (scratch copy, Astro 7.4.13):**
- With `redirectToDefaultLocale: true`, the build **fails** with `MissingIndexForInternationalization` unless `src/pages/index.astro` exists. An empty one (`---\n---`) is enough: the build emits `dist/index.html` with `<meta http-equiv="refresh" content="2;url=/es/">`, `noindex` and a canonical link to `/es/`.
- Inside `src/pages/[locale]/…`, `Astro.currentLocale` returns `es` or `en` correctly.
- `getAbsoluteLocaleUrl('en', 'styleguide')` returns `https://juaniw.com/en/styleguide/`, and `getAbsoluteLocaleUrl('en')` returns `https://juaniw.com/en/` (both with a trailing slash).

## Global Constraints

- **Dictionaries:** prose only. Facts stay literal and identical in both languages: token names, values, class names, font names, theme names (Salvia, Brasa), contrast pair labels (`text / bg`), product and tool names (VS Code, Configs, AI Configs). (Q4)

## Review Focus

1. **Spanish leftovers on `/en/styleguide/`:** a single untranslated string is the most likely failure. Task 3 greps `dist/en/styleguide/index.html` for a list of Spanish words.
2. **`lang` mismatch:** `/en/…` must render `<html lang="en">`. Task 1 greps both locales.
3. **Alternates on nested paths:** on `/en/styleguide/`, the `es` alternate must point to `/es/styleguide/`, not `/es/`. Task 1 checks it.
4. **Unknown locale (`/fr/`, `/styleguide`):** must not be generated. Task 1 checks that `dist/` contains only the expected HTML files.
5. **Missing key in one dictionary:** must break `npm run check`. Task 2 proves it by temporarily deleting one key from `en.ts`.

  - `export const locales = ['es', 'en'] as const;` (with a comment saying it must match `i18n.locales` in `astro.config.mjs`)
  - `export type Locale = (typeof locales)[number];`
  - `export const defaultLocale: Locale = 'es';`
  - `export function isLocale(value: string | undefined): value is Locale`
  - `export function localeStaticPaths(): { params: { locale: Locale }; props: { locale: Locale } }[]`

- `Layout.astro` props become `{ title: string; description?: string }`.
