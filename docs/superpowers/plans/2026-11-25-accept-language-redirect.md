# `/` language detection (Accept-Language) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A request to `juaniw.com/` gets a 307 to `/es/` when the visitor's preferred language is Spanish, and to `/en/` otherwise. Today it always gets a 301 to `/es/`.

**Architecture:** A minimal hand-written Cloudflare Worker (`src/worker.ts`) is added next to the existing static assets. `wrangler.jsonc` gets `main` and `assets.run_worker_first: ["/"]`, so the Worker runs **only** for `/`. Every other URL keeps being served straight from `dist/` with no Worker invocation. The language choice is a pure function (`src/i18n/acceptLanguage.ts`), unit-tested with `node --test` like `src/scripts/notFoundPath.ts`. Astro's build, pages and config stay as they are: no adapter, no on-demand rendering.

**Tech Stack:** Cloudflare Workers static assets + Wrangler 4.168 (`main`, `assets.run_worker_first`), TypeScript, Node `node:test` (Node strips types; imports between tested files use the `.ts` extension, allowed by `allowImportingTsExtensions` in `astro/tsconfigs/base.json`).

**Spec:** `design/diseno-juaniw.md:66` (redirect of `/`: "Si el primer idioma es español (`es`, `es-AR`, etc.), va a `/es`; en cualquier otro caso, a `/en`. Es una redirección 307"), `design/copy-mvp.md:43`, and `TODO.md:14`. The grilling session on 2026-11-25 settled the overrides listed under Global Constraints.

**Astro docs consulted (astro-docs MCP):**
- `Astro.preferredLocale` only works on routes rendered on demand, not on prerendered pages, which is why detection can't live in `src/pages/index.astro`: https://docs.astro.build/en/reference/api-reference/#preferredlocale and https://docs.astro.build/en/guides/internationalization/#browser-language-detection
- A static Astro site on Cloudflare Workers needs no adapter. The wrangler config only has `assets.directory`: https://docs.astro.build/en/guides/deploy/cloudflare/
- `_redirects` applies to static assets. Headers and redirects from `public/` don't apply to responses generated by Worker code: https://docs.astro.build/en/guides/integrations-guide/cloudflare/#cloudflare-platform

**Verified in the repo:** `node_modules/wrangler/config-schema.json` accepts `run_worker_first` as `boolean | string[]` ("Matches will be routed to the User Worker").

## Global Constraints

- **Mechanism (Q1 = B):** a hand-written Worker. Do **not** add `@astrojs/cloudflare`, `output: 'server'` or `prerender = false`. `astro.config.mjs` doesn't change.
- **Scope (Q2):** only the exact path `/`. `run_worker_first: ["/"]`. Unprefixed paths like `/now/` keep going to the 404.
- **Choice rule (Q3):** parse `Accept-Language`, drop entries with `q=0` or an invalid `q`, sort by `q` descending (stable, so ties keep header order), take the first entry. If its primary subtag, case-insensitive, is exactly `es`, the result is `es`. In every other case it's `en`. `*` counts as "not es".
- **Missing, empty or unparseable header (Q4):** `en`.
- **Response (Q5):** status `307`, `Location` = absolute URL `/{locale}/` on the request's origin, keeping the query string. Headers: `Vary: Accept-Language` and `Cache-Control: no-store`. Every method (GET, HEAD, others) gets the same redirect.
- **No cookie or remembered choice (Q6).**
- **All docs, comments and commit messages in English** (`CLAUDE.md`).

## Review Focus

1. **Query strings on shared links:** `/?utm_source=linkedin` → `/en/?utm_source=linkedin`. Losing campaign params would be a silent regression. Test in Task 2.
2. **Regional and upper-case tags:** `es-AR`, `es-419`, `ES` → `es`. A tag that starts with "es" but isn't Spanish (`est`) → `en`. Test in Task 1.
3. **A Spanish speaker who ranks English first:** `en-US,en;q=0.9,es;q=0.8` → `en` (what the spec asks for: the *first* language). Test in Task 1.
4. **Explicit rejection:** `es;q=0, en` → `en`. An invalid weight `es;q=abc, en;q=0.5` → `en`. Test in Task 1.
5. **Every other URL still comes from assets:** `/es/`, `/en/now/`, `/favicon.svg` and a missing URL (custom 404) must behave the same as before. Check by hand in Task 2, Step 6.
